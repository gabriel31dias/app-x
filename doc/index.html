Orama Games · Provedor de jogos

Coloque os jogos da Orama Games no seu cassino com uma integração.

A API da Orama Games entrega nosso catálogo de jogos originais para operadores. O saldo continua na sua plataforma: nós só pedimos para debitar a aposta e creditar o prêmio, com assinatura em cada chamada e idempotência de ponta a ponta.

12jogos originais
85–99%RTP configurável por jogo
6endpoints + 4 callbacks
BRLPIX-ready, mobile first

Como funciona

A integração segue o padrão seamless wallet: o jogador nunca transfere saldo para a Orama Games. Cada jogada vira um débito e um crédito na carteira que você já tem.

1
Abrir sessão

Seu back-end chama POST /sessions com o jogador e o jogo.

2
Carregar o jogo

Você recebe uma launchUrl e abre em iframe ou nova aba.

3
Jogada

Chamamos /bet na sua carteira, sorteamos no nosso servidor e chamamos /win.

4
Conciliação

Tudo fica em GET /rounds e no relatório de GGR do mês.

O resultado é sempre sorteado no servidor da Orama Games. O jogo no navegador só mostra a animação do resultado que já foi decidido e pago, então não há como alterar prêmio pelo cliente.

Autenticação e assinatura

Você recebe duas credenciais no cadastro: o operatorId e o secret. O secret nunca trafega; ele só é usado para assinar.

Toda requisição, nas duas direções, leva estes cabeçalhos:

CabeçalhoValor
X-Operator-IdSeu identificador, ex.: op_7Hq2mK
X-TimestampUnix em segundos. Recusamos diferenças maiores que 300 s.
X-Signaturehex(HMAC-SHA256(secret, timestamp + "." + corpo)). Em GET, o corpo é a query string sem o ?.
Content-Typeapplication/json
import crypto from 'node:crypto';

function assinar(secret, corpo) {
  const ts = Math.floor(Date.now() / 1000).toString();
  const sig = crypto.createHmac('sha256', secret).update(`${ts}.${corpo}`).digest('hex');
  return { 'X-Timestamp': ts, 'X-Signature': sig };
}

// validar um callback recebido da Orama Games (compare em tempo constante)
function valido(secret, ts, corpoBruto, sig) {
  if (Math.abs(Date.now() / 1000 - Number(ts)) > 300) return false;
  const esperado = crypto.createHmac('sha256', secret).update(`${ts}.${corpoBruto}`).digest();
  return crypto.timingSafeEqual(esperado, Buffer.from(sig, 'hex'));
}

Convenções

  • Valores em centavos, sempre inteiros: 500 = R$ 5,00. Nunca use ponto flutuante para dinheiro.
  • Moeda no padrão ISO 4217. Hoje: BRL.
  • Datas em ISO 8601 UTC: 2026-09-29T14:03:11Z.
  • Idempotência: todo débito e crédito tem um transactionId único. Se ele chegar de novo, responda com o mesmo resultado da primeira vez, sem mover saldo.
  • playerId é o identificador do jogador na sua plataforma. Não pedimos nem guardamos CPF, e-mail ou nome.
  • Respostas de erro seguem sempre o formato {"error": {"code": "...", "message": "..."}}.

Carteira seamless: os callbacks

Estes são os endpoints que você implementa. Nós chamamos em {callbackUrl}/balance, /bet, /win e /rollback, sempre por POST e com os cabeçalhos de assinatura. Valide a assinatura antes de mexer em qualquer saldo.

Regras de ouro: (1) mesmo transactionId → mesma resposta, sem mover saldo de novo; (2) responda em até 3 s; (3) um /win ou /rollback nunca pode ser recusado por saldo; (4) um /rollback de uma aposta que você não conhece deve responder 200 (nada a desfazer).

Toda resposta de sucesso devolve o saldo atualizado:

Resposta padrão 200
{ "balance": 12350, "currency": "BRL" }

POST{callbackUrl}/balance

/win

POST{callbackUrl}/win

Credita o prêmio e fecha a rodada. É enviado mesmo quando o prêmio é zero (amount: 0), para você saber que a rodada terminou. Se falhar, tentamos de novo com o mesmo transactionId por até 24 h (1 s, 5 s, 30 s, 2 min, depois a cada 10 min).

Corpo enviado
{
  "transactionId": "tx_01J8Z4",
  "betTransactionId": "tx_01J8Z3",
  "roundId": "rnd_01J8Z3M7",
  "playerId": "u_1029",
  "gameId": "crash",
  "amount": 1150,
  "currency": "BRL",
  "roundClosed": true
}

/rollback

POST{callbackUrl}/rollback

Desfaz uma aposta cujo /bet deu erro de rede ou passou do tempo. Devolva o valor debitado, se houver. Se a aposta nunca chegou, responda 200 do mesmo jeito.

Corpo enviado
{
  "transactionId": "tx_01J8Z5",
  "betTransactionId": "tx_01J8Z3",
  "roundId": "rnd_01J8Z3M7",
  "playerId": "u_1029",
  "amount": 500,
  "currency": "BRL"
}

Exemplo de implementação (Node.js + Postgres)

/bet idempotente
app.post('/orama/bet', async (req, res) => {
  if (!valido(SECRET, req.get('X-Timestamp'), req.rawBody, req.get('X-Signature')))
    return res.status(401).json({ error: { code: 'INVALID_SIGNATURE' } });

  const { transactionId, playerId, amount } = req.body;
  const r = await db.tx(async (t) => {
    const ja = await t.oneOrNone('select resposta from orama_tx where id = $1', [transactionId]);
    if (ja) return ja.resposta;                          // repetido: mesma resposta
    const u = await t.one('select saldo from carteira where player = $1 for update', [playerId]);
    const resposta = u.saldo < amount
      ? { status: 402, body: { error: { code: 'INSUFFICIENT_FUNDS' } } }
      : { status: 200, body: { balance: u.saldo - amount, currency: 'BRL' } };
    if (resposta.status === 200) await t.none('update carteira set saldo = saldo - $2 where player = $1', [playerId, amount]);
    await t.none('insert into orama_tx (id, resposta) values ($1, $2)', [transactionId, resposta]);
    return resposta;
  });
  res.status(r.status).json(r.body);
});

Catálogo de jogos

Todos os jogos são originais da Orama Games, feitos para celular e com RTP ajustável entre 85% e 99% (o piso segue o mínimo exigido para jogo online no Brasil).

RTP e fairness

  • RTP por operador e por jogo: você escolhe entre as opções de rtpOptions no painel. A troca vale para as rodadas novas, nunca para uma rodada em andamento.
  • Sorteio no servidor com gerador criptográfico. O navegador só recebe o resultado.
  • Provably fair: publicamos o hash da seed do servidor antes das rodadas e revelamos a seed na rotação. Qualquer um pode refazer a conta a partir de serverSeed + nonce.
  • Limite de prêmio por rodada (maxWin) configurável, para proteger o caixa do operador.

Checklist de homologação

Antes de liberar as chaves de produção, rodamos estes testes no sandbox contra a sua carteira:

  • Assinatura inválida em qualquer callback → você responde 401.
  • /bet repetido com o mesmo transactionId → debita uma vez só.
  • /bet sem saldo → 402 INSUFFICIENT_FUNDS, sem mudar o saldo.
  • /win com amount: 0 → 200 com o saldo.
  • /win repetido → credita uma vez só.
  • /rollback de aposta existente → devolve o valor; de aposta desconhecida → 200.
  • /rollback repetido → devolve uma vez só.
  • Todos os callbacks respondem em menos de 3 s.
  • Conciliação de um dia de GET /rounds bate com a sua carteira.
